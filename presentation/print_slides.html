OVERHEATING NEEDS AN EARLY, STABLE RESPONSE
> detect before damage.
02
PROBLEM

Abnormal machine temperature can cause equipment damage, production interruptions, and safety concerns.

SCOPE

Software prototype with simulated sensor data, not a physical industrial installation.

MONITOR · ALARM · SAFETY
  • MONITOR: Monitor simulated temperature data through a ROS 2 node.
  • ALARM: Activate an alarm at a high threshold and clear it safely below a low threshold.
  • SAFETY: Detect stale data (>1.0s) and provide a reset service.
TWO ROS 2 NODES TURN READINGS INTO MACHINE STATUS
A topic carries readings forward; a reset service returns a controlled request.
03
NODE 01: Simulated Temperature Sensor Node

Primary Function: Publishes simulated readings at 10 Hz.

  • Topic: /machine/temperature
  • Message Type: sensor_msgs/msg/Temperature

Topic path: Simulated Temperature Sensor Node → ROS 2 topic: /machine/temperature → Temperature Monitoring Node

NODE 02: Temperature Monitoring Node

Functions: EMA filtering · threshold comparison · timeout detection.

  • Parameters: high 80°C · low 75°C · EMA α 0.2 default · stale timeout 1 second
  • Outputs: /machine/alarm (Bool) · /machine/status (String)
  • Reset Service: /machine/reset (Trigger)
HYSTERESIS PREVENTS REPEATED ALARM SWITCHING
1 Receive (Temperature reading) → 2 Filter (Apply EMA) → 3 Compare (Thresholds)
04
THRESHOLD BEHAVIOUR
  • 80°C HIGH: At or above 80°C: activate the alarm.
  • HYSTERESIS ZONE: Between 75°C and 80°C: hold the existing state.
  • 75°C LOW: Below 75°C: clear the alarm.
  • SAFETY: Reject reset when temperature is unsafe or data is stale.
FILTER EQUATION
FilteredTemperature = α × CurrentReading +
(1 − α) × PreviousFilteredTemperature

α balances the latest reading against previous filtered readings:

  • α = 0.2: Low-pass filtering attenuating vibration chatter.
  • α = 1.0: Deterministic evaluation for testing.
